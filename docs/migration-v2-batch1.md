# 第二版第一批：管理员站点授权与认证版本迁移

本批只增加数据库结构、底层实体和 Mapper。不修改登录、JWT、Filter、接口、前端或公司资料；`auth_version` 暂不参与认证、不自动递增。不得仅凭新增关联记录认为第二版访问控制已经生效。

## 文件及前置条件

按顺序执行 `sql/` 下的三个文件：

1. `event_system_v2_admin_site_precheck.sql`：只读预检。
2. `event_system_v2_admin_site_schema.sql`：一次性结构迁移及结构核验。
3. `event_system_v2_admin_site_backfill.sql`：历史 EDITOR 授权回填及缺失授权核验。

要求 MySQL **8.0.16 或以上**（需要实际执行 CHECK 约束）、InnoDB，且已执行多站点基础迁移 `event_system_v2_multisite_foundation.sql`。已有主键和关联字段为 `BIGINT UNSIGNED`，保留原 `site_config` 的 `UNIQUE(site_id)` 和 `site_domain` 的域名全局唯一索引。

脚本不包含 `USE`。使用客户端连接参数显式选择目标数据库；首次验证必须使用独立 MySQL 测试库，不连接开发库。密码通过交互输入或受保护的客户端配置提供，不写入脚本、命令行参数或提交文件。

## 执行前检查与备份

1. 确认连接地址、选中库名和 MySQL 版本，客户端使用 `autocommit=1`；保存四张基线表的 `SHOW CREATE TABLE` 结果以及站点 ID、编码、状态、域名、配置、管理员数量和更新时间快照。
2. 在独立测试库完成迁移演练。正式迁移进入维护状态，停止所有实例、定时任务等写入，完成一致性全库备份并确认可恢复。所有 DDL 可能持有元数据锁，预留维护窗口。
3. 运行只读预检：启用的默认站点数量必须为 **1**；非法状态、非法主域名标志、多个主域名、配置缺失、未知未删除管理员角色的数量必须为 **0**。新增表、列、约束的已存在数量必须为 **0**。核对结构中的类型、唯一索引及存储引擎。
4. 预检任何异常都先停止，不自动修复或赋权。已存在批次对象意味着可能已执行或部分执行，不能从头盲目重跑。

旧站点可能只有本地域名别名、没有主域名；预检将其列为提示，不在本批擅自选择主域名。新增约束保证**至多一个主域名**，后续服务层负责创建及编辑时恰好一个主域名。默认站点不可停用等业务规则留到站点管理批次实现。

## 结构迁移与回填

1. 执行结构脚本，客户端启用遇错即停，**禁止使用 `--force` 继续执行**。MySQL DDL 隐式提交，外围 `BEGIN/ROLLBACK` 不能使整份结构脚本具备事务性。
2. 核对生成列、主域名唯一索引、站点状态 CHECK、标志 CHECK、认证版本 CHECK、复合主键、反向索引及两个外键。别名生成值为 NULL，允许多个别名；主域名生成值等于站点 ID，每站点至多一个。
3. 核对所有历史账号 `auth_version=0`，历史站点状态和业务数据保持原值。历史站点的新增时间字段为迁移时间，不代表实际历史创建时间。`site.status` 默认值改为 `DISABLED` 只作用于未来省略状态的新增记录。
4. 回填脚本按 `site.code='default'` 查找默认站点，**先单独确认数量为 1，再执行 INSERT**。不要假定默认站点 ID 为 1。
5. 回填所有 `role_code='EDITOR' AND deleted=0` 的管理员，包括禁用账号；不为超管或已删除账号添加授权。已有绑定保留原授权时间；复合主键及 `NOT EXISTS` 防止重复。单条 INSERT 原子提交，遇到外键等错误直接失败，不使用 `INSERT IGNORE` 掩盖异常。
6. 缺失默认站点授权的普通管理员数必须为 0；核对新增加的数量和预检预期一致，没有非默认站点的新授权。保留现场核验记录后再部署本批后端。

回填只允许在本次维护窗口内、恢复授权管理业务之前重跑。未来上线授权撤销功能后再次运行，会恢复管理员主动撤销的默认站点授权，届时禁止作为日常初始化脚本使用。

## Java 映射与兼容

- `AdminUser.authVersion` 使用 `Long`，Java 默认 `0L`，数据库同时提供 `DEFAULT 0`，兼容旧代码及 seed 的新增账号路径。
- `AdminUserSite` 只有两个键及授权时间；不声明伪单主键，不对站点字段应用自动填充。
- `AdminUserSiteMapper` 不继承 `BaseMapper`。单条查询、存在性检查、删除都显式传入管理员 ID 与站点 ID；列表及批量撤销显式传入管理员 ID。新增使用标量参数，时间由数据库生成。
- `admin_user_site` 加入全局表清单，查询不会受当前租户限制。该 Mapper 不等于鉴权入口，后续管理服务必须先验证超管权限再调用。
- 本批没有接口变更，现有 Swagger 文档接口继续通过原有集成测试验证。

## 测试与核验边界

JUnit 使用 `test` Profile 下的独立 H2 内存数据库，不加载开发库连接。测试结构模拟新字段和约束；H2 生成列使用等价表达式，不带 MySQL `STORED`。Maven 将实际交付的回填脚本加入测试资源，因此测试直接执行同一份回填 SQL，不维护另一份实现副本。

新增持久化集成测试覆盖默认认证版本及更新、复合主键、多对多关系、外键及撤销隔离、跨 SiteContext 显式写入/查询、回填过滤和重复运行、主域名生成值及唯一性、状态/标志/版本约束。修改完成后执行全部 `mvn test`，不得跳过失败项。

MySQL 的完整 DDL、生成列、索引及外键行为必须另在独立 MySQL 测试库验证；H2 通过不代表 MySQL 验证通过。交付记录需明确实际验证环境和结果，无法验证时如实注明。

## 失败与恢复

- **结构迁移失败：** 保持维护状态，保存错误、已成功执行的语句和当前 `SHOW CREATE TABLE`，不要靠重新运行整份脚本恢复。根据备份在独立恢复环境核对后恢复整个目标库，或由数据库维护人员审核只包含剩余变更的补救脚本。
- **回填失败：** 检查前置默认站点及结构是否正确，保持停写；该 INSERT 不会部分提交，修复问题后可以在维护窗口内重跑回填。
- **应用部署失败：** 保持维护状态，协调应用和数据库备份恢复；不要在已开展授权管理后直接回退旧认证代码。第一批没有改变认证行为，也不失效已有 JWT；后续认证批次另行安排令牌兼容策略。
- 不提供可能误删后续授权及认证版本的自动降级 SQL；完整回退以迁移前可恢复的数据库备份为准。
